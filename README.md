運動規劃小幫手：規格說明
1. 專案概述

名稱：運動規劃小幫手
類型：純前端單頁網頁（HTML、CSS、JavaScript），部署在 GitHub Pages
一句話說明：回答幾個問題、選擇訓練方式後，產生一週運動菜單與對應的飲食建議。

2. 背景與動機

很多人想開始運動，卻不知道該做重訓、有氧還是 HIIT，也不知道一週怎麼排、飲食要怎麼配合。網路資訊零散，初學者容易不知所措或選錯方式而放棄。這個網頁把這些決策整理成三個步驟，讓使用者在幾分鐘內拿到可以直接照做的計畫。

3. 目標使用者

想運動但不知道如何規劃與實行的人，特別是新手，以及有一些基礎、想重新安排訓練的人。

4. 核心功能
功能	說明
條件輸入	目標（增肌／減脂／維持健康）、每週運動天數（2–6 天）、每次時間（20／30／45／60 分鐘）、器材（無器材／啞鈴／健身房）、經驗（新手／有基礎）、體重（選填）
訓練方式模塊	重量訓練、有氧運動、HIIT 各為一個模塊，列出適合誰、優點、注意事項、增肌／燃脂／心肺／新手友善的評分，並依使用者條件標示「推薦」，可自由增減
一週運動菜單	依條件與所選模塊，自動排出週一到週日的內容，包含熱身、動作、組數次數、組間休息、緩和
飲食建議	依目標提供飲食原則、餐盤比例、每日蛋白質目標、三餐與點心範例、外食與超商選擇、運動前後飲食
輸出與保存	可列印或存成 PDF；填寫內容自動存在瀏覽器，重新整理後仍保留
5. 使用流程
你的條件：填寫目標、天數、時間、器材、經驗。
訓練方式：系統依目標與經驗預選推薦的模塊，使用者可調整，至少選一種。
我的菜單：以「運動菜單」與「飲食建議」兩個分頁呈現結果，並可回到前面步驟修改。
6. 菜單產生規則（規則式模板）

網頁不使用 AI 即時生成，而是以預先寫好的規則與動作資料組合，結果穩定、可預測。

運動日安排：依天數固定分布（例如 3 天為週一、三、五），避免連續訓練，其餘為休息日。
各類訓練次數：依目標給予權重（例如減脂：重訓 40%、HIIT 30%、有氧 30%），在使用者所選模塊中逐次分配。
安全上限：重訓每週最多 4 次；HIIT 新手每週最多 1 次、有基礎最多 2 次，且不排在連續兩天。超出上限的日子改為「主動恢復日」。
重訓內容：新手採全身訓練 A／B 交替；有基礎者視次數採上半身／下半身分化。動作依器材條件選擇，動作數量依每次時間決定（3–6 個）。組數與次數依目標與經驗調整（例如增肌 8–12 下、減脂 12–15 下）。
有氧內容：新手以能說話但有點喘的強度為主；有基礎者加入「稍快與輕鬆」的間歇。
HIIT 內容：新手為 30 秒運動／30 秒休息，有基礎為 40 秒／20 秒，並依時間計算圈數。
7. 飲食建議規則
依三種目標各有一組飲食原則、餐盤比例與餐點範例（以台灣常見的便當、超商、自助餐為主）。
填寫體重時，換算每日蛋白質範圍：增肌每公斤 1.6–2.0 公克、減脂 1.4–1.8 公克、維持健康 1.2–1.6 公克。
不提供精確熱量計算，也不建議極端節食。
8. 畫面設計
色彩取自運動場地：場地藍為主色、哨音黃作重點、墊子灰作輔助；三種訓練各有代表色（重訓深藍黑、有氧青綠、HIIT 珊瑚紅）。
字體使用 Noto Sans TC（內文）與 Barlow Condensed（英文標題與數字），帶有運動標示的感覺。
一週總覽以七格色條呈現，點擊可跳到當天內容。
響應式設計，手機與電腦皆可使用；按鈕具鍵盤焦點樣式，並尊重「減少動態效果」設定。
9. 資料與技術
技術：單一 index.html，無後端、無外部套件，僅載入 Google Fonts（載入失敗時使用系統字體）。
資料儲存：動作與餐點資料寫在程式內的資料表；使用者選擇存在瀏覽器 localStorage，不上傳任何資料。
部署：GitHub Pages，由 main 分支根目錄提供。
10. 不做的事（範圍限制）
不做登入與帳號。
不做運動紀錄與進度追蹤。
不做醫療診斷或個人化處方。
不串接 AI API。原因是金鑰放在公開網頁上有外洩風險，且規則式結果更穩定。
11. 免責聲明

內容為一般性運動與飲食參考，不是醫療建議。有心血管疾病、關節傷病、懷孕、慢性病、腎臟疾病，或運動時出現胸痛、頭暈等不適者，應先諮詢醫師或專業教練。

12. 驗收標準
所有條件組合都能產生菜單，且畫面沒有錯誤。
只選 HIIT 時，不會連續天數排 HIIT。
填入體重後，飲食頁顯示對應的蛋白質公克數。
重新整理頁面後，先前的選擇仍保留。
手機與電腦版面皆可正常閱讀與操作。
